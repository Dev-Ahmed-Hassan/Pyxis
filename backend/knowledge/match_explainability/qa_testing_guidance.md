# QA Testing Guidance

This document supports QA, software testing, and automation testing roles.

## QA Engineer Role Signals

chunk_type: career
field: software_engineering
role: QA Engineer Intern
skills: test cases, bug reports, manual testing, regression testing
purpose: role-fit

QA internships usually value evidence of writing test cases, reproducing bugs,
documenting expected and actual behavior, regression testing, and communicating
clearly with developers. Strong evidence includes test plans, bug reports,
checklists, and screenshots or logs.

Strong evidence names:

```text
feature tested
test scenario
expected result
actual result
bug severity
reproduction steps
```

## Automation Testing Role Signals

chunk_type: career
field: software_engineering
role: Automation Testing Intern
skills: Selenium, Playwright, pytest, unit testing, API testing
purpose: role-fit

Automation testing roles value evidence of writing repeatable tests. Strong
evidence includes unit tests, API tests, UI automation, CI test execution, test
reports, and clear assertions.

Partial evidence includes using an app manually without documenting tests.

## API Testing Project Suggestion

chunk_type: project
field: software_engineering
role: QA Engineer Intern
skills: API testing, Postman, pytest, test cases
purpose: missing-skill-project

Use this project when the student lacks testing evidence.

Project:

```text
Create a small API and write test cases for successful requests, validation
errors, authentication failures, and edge cases using pytest or Postman.
```

Resume bullet:

```text
Designed API test cases covering valid requests, validation errors,
authentication failures, and edge cases using pytest/Postman.
```

## QA Interview Guidance

chunk_type: interview
field: software_engineering
role: QA Engineer Intern
skills: test planning, bug reporting, automation
purpose: interview-prep

Common QA interview questions:

```text
How do you write a good bug report?
What is regression testing?
What is the difference between unit, integration, and end-to-end testing?
How would you test a login page?
What makes a test case useful?
```

Strong answers should be structured, reproducible, and focused on quality.
